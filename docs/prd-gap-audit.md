## Feature selected

Host Lounge creation and invite joining were selected because the backend contract and authorized gateway existed, but the central Host journey was disconnected from the UI. That blocks the PRD's main live demonstration and is more foundational than polishing sample Home or album previews. The feature reuses the Queue screen, existing catalog/API client and Socket.io path; no new backend stack or visual system is introduced.

Acceptance path: a Host signs in, selects a catalog starter, configures vibe/capacity/BPM tolerance/Soundclash/AI verbosity, creates the Lounge, receives an invite code and connects to its queue; a same-browser reload can rejoin from the saved invite; a second authenticated Listener joins with the code and receives the same Now Playing snapshot. The Playwright test verifies the persisted Mongo Lounge fields and settings. The server remains authoritative for role, invite validity, capacity and membership.

## Durable Lounge session analytics increment (2026-10-21)

New Lounge sessions persist sequenced unique-user presence edges and successful AI DJ question events. A per-user idempotency key prevents accepted Q&A retries from being counted again without saving the question text. End summaries, Lounge history, and the member-scoped analytics endpoint calculate duration, distinct battle count, peak participant count, AI question count, chat count, and sentiment points from persisted timestamps and event records. Legacy sessions with no completeness marker return unavailable values for peak/questions. Analytics omits user IDs, invite codes, request IDs, and chat text. Peak recovery across process restarts is guarded by persisted participant-count consistency; if the replay does not reconcile, the metric is unavailable instead of guessed.

The MongoDB fixture's source log was manually reconciled to: 60-second duration (in unit fixture), four queue events with one distinct battle, five presence edges with peak two, two unique authenticated AI requests despite one retry, and three ordered sentiment samples. In the real Mongo integration, the HTTP analytics/history results exactly equal the persisted end summary and an unrelated account receives 403/empty history. The local Playwright Lounge E2E confirmed the Profile displays `Peak 2 · 0 AI questions · 0 sentiment samples` for its two connected members. Remaining PRD gaps include legacy backfill/coverage, acoustic taste, multi-replica state, measured performance, sentiment accuracy, and the recorded full-session walkthrough.

Validation: backend unit suite — 96 passed, 5 opt-in Mongo tests skipped; backend Mongo integration suite — 101 passed, 0 skipped; frontend tests — 15 passed; Lounge Playwright E2E — 1 passed; production build and `git diff --check` — passed. These are local runs against an isolated disposable Mongo database, not production verification.

## Persistent user settings increment (2026-10-21)

`Settings persistence and runtime behavior` remains Partial. Seven Audio values remain stored per authenticated account. AI DJ commentary now affects the real segue result presentation and the Socket.io Lounge DJ announcement display; disabling it does not disable the acoustic segue request or queue synchronization. Streaming quality, crossfade, volume normalization, lyrics, download quality and autoplay remain saved-only; their controls are disabled with capability explanations because there are no alternate sources, crossfade lifecycle, loudness data/processor, lyrics provider, download path, or authoritative queue advance. A focused UI-data test verifies that disabling commentary hides only the transition text and preserves the accepted selection and match reason.
