## Feature selected

Host Lounge creation and invite joining were selected because the backend contract and authorized gateway existed, but the central Host journey was disconnected from the UI. That blocks the PRD's main live demonstration and is more foundational than polishing sample Home or album previews. The feature reuses the Queue screen, existing catalog/API client and Socket.io path; no new backend stack or visual system is introduced.

Acceptance path: a Host signs in, selects a catalog starter, configures vibe/capacity/BPM tolerance/Soundclash/AI verbosity, creates the Lounge, receives an invite code and connects to its queue; a same-browser reload can rejoin from the saved invite; a second authenticated Listener joins with the code and receives the same Now Playing snapshot. The Playwright test verifies the persisted Mongo Lounge fields and settings. The server remains authoritative for role, invite validity, capacity and membership.

## Durable Lounge session analytics increment (2026-10-21)

New Lounge sessions persist sequenced unique-user presence edges and successful AI DJ question events. A per-user idempotency key prevents accepted Q&A retries from being counted again without saving the question text. End summaries, Lounge history, and the member-scoped analytics endpoint calculate duration, distinct battle count, peak participant count, AI question count, chat count, and sentiment points from persisted timestamps and event records. Legacy sessions with no completeness marker return unavailable values for peak/questions. Analytics omits user IDs, invite codes, request IDs, and chat text. Peak recovery across process restarts is guarded by persisted participant-count consistency; if the replay does not reconcile, the metric is unavailable instead of guessed.

The MongoDB fixture's source log was manually reconciled to: 60-second duration (in unit fixture), four queue events with one distinct battle, five presence edges with peak two, two unique authenticated AI requests despite one retry, and three ordered sentiment samples. In the real Mongo integration, the HTTP analytics/history results exactly equal the persisted end summary and an unrelated account receives 403/empty history. The local Playwright Lounge E2E confirmed the Profile displays `Peak 2 · 0 AI questions · 0 sentiment samples` for its two connected members. Remaining PRD gaps include legacy backfill/coverage, multi-replica state, measured performance, sentiment accuracy, and the recorded full-session walkthrough.

Validation: backend unit suite — 96 passed, 5 opt-in Mongo tests skipped; backend Mongo integration suite — 101 passed, 0 skipped; frontend tests — 15 passed; Lounge Playwright E2E — 1 passed; production build and `git diff --check` — passed. These are local runs against an isolated disposable Mongo database, not production verification.

## Acoustic taste profile and recommendation evaluation (2026-10-22)

The authenticated `GET /api/v1/recommendations/taste` endpoint and Profile panel compute preferences from the caller's persisted interaction rows and valid Track acoustic profiles. Full completions and likes have weight 1; an incomplete, unliked report weighs its reported duration fraction; a zero-second skip weighs 0. Invalid/missing acoustic profiles and malformed reports do not contribute. The profile needs two distinct eligible tracks; preference aggregation uses each track's strongest report once, while source-row counts and track/acoustic coverage are shown separately. This prevents repeats from silently multiplying a single track but cannot distinguish a legitimate replay from a retried report. Taste is recomputed at read time, not cached. The same profile threshold now gates the acoustic recommendation signal; qualified collaborative-only recommendation behavior remains available. Immediate segue hard constraints and its 50/30/20 weights are unchanged.

Reproducible synthetic evaluation: two evaluation-user tracks are training inputs; a separate ten-track candidate set contains three held-out relevant labels selected to be acoustically close to those inputs. `Precision@5 = distinct relevant tracks in the top five / 5`; acoustic content ranking is 3/5 = 0.60. Popularity is ranked from separate synthetic training-cohort counts and scores 0/5. The fixture has one user and labels deliberately aligned with its acoustic seed, so it is a calculation/regression check, not independent relevance, real-user effectiveness, or statistically meaningful evidence. It is not sufficient by itself to claim the PRD recommendation target is met in deployment.
